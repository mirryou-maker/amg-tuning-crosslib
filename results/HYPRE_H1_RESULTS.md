## H1 게이트: 통과 — hypre에도 튜닝 여지 있음

hypre 기본값(Falgout+L1symGS+strong0.25) 기준 per-matrix oracle:
- n=11, 중앙값 **1.75**, Q3 **2.09**, 최대 **3.27**, 8/11이 ≥1.5배.
- 승리 조합이 갈림(PMIS-8·HMIS-10, relax 3/6/18, strong 0.25/0.5/0.7 다양) → H2/H3 유의미.

## 핵심 발견 (예상보다 중요): "튜닝 이득의 크기는 기본값 품질에 반비례"

머리 맞댄 oracle (같은 11행렬):

| 행렬 | AMGCL oracle | hypre oracle |
|---|---|---|
| Hamm/memplus | **292배** | 1.88배 |
| Cunningham/qa8fm | 53.5배 | 2.09배 |
| Averous/epb1 | 20.5배 | 1.39배 |
| Pothen/bodyy6 | 9.3배 | 1.52배 |
| GHS_indef/bloweybq | 3.76배 | 3.27배 |
| GHS_psdef/wathen100 | 2.39배 | 2.34배 |

**AMGCL의 극단적 speedup은 hypre에서 재현되지 않는다.** 왜?
기본값끼리 직접 비교(같은 행렬, 각 라이브러리 기본 설정):

| 행렬 | AMGCL 기본 | hypre 기본 | 비 |
|---|---|---|---|
| Hamm/memplus | 7.31s | 0.017s | hypre 430배 빠름 |
| Cunningham/qa8fm | 5.33s | 0.080s | 66배 |
| FlowIPM22/Spielman_k100 | 6.71s | 0.61s | 11배 |
| ... | | | hypre가 9/11에서 우세 |

→ **AMGCL의 거대한 oracle(292배 등)은 상당 부분 AMGCL 기본값이 그 행렬에서
나쁘기 때문**이지, 행렬의 내재적 튜닝 여지가 그만큼 커서가 아니다. hypre의
기본값(LLNL이 수십 년 다듬은 Falgout+L1GS)은 이미 강건해서 개선 여지가 작다.
(주의: 절대시간은 구현·CSR·Krylov 차이가 있으니 경향으로만 해석.)

## 학문적 재구성 (오히려 더 강해짐)

단순 "AMGCL 결과가 재현된다"가 아니라, 더 정교한 발견:
1. **내부 파라미터 튜닝은 두 표준 AMG 모두에서 이득이 있다**(정성적 일반화, H1 통과).
2. **그러나 이득의 크기는 라이브러리 기본값 품질에 강하게 의존한다.** 약한
   기본값(AMGCL)→극적 이득, 강한 기본값(hypre)→modest 이득(중앙 1.75배).
3. **실용적 함의**: 파라미터 자동튜닝은 기본값이 약한 설정에서 가장 가치 크다.
   잘 다듬어진 hypre에서도 실질 이득은 있으나 과장하면 안 된다.
4. **부분 일관성**: bloweybq(3.76/3.27)·wathen100(2.39/2.34)처럼 두 라이브러리에서
   비슷한 튜닝 민감도를 보이는 행렬도 있음 → 일부는 행렬 내재적 성질.
