# H4: hypre 예측기 + 교차 라이브러리 전이 (2026-07-29)

로컬 실험(기존 데이터 재사용). 도구 `tools/hypre_h4.py`. 전부 leave-one-group-out.
config 공간이 라이브러리마다 달라 config-수준 모델은 전이하지 않고, **행렬-수준
양(풀림 여부·oracle 크기)** 만 라이브러리 독립 특징공간에서 전이.

## 1. hypre 예측기 (AMGCL 방식 그대로 hypre에)
- 평가행렬 45, 선택조합 **성공 87%**(39/45), oracle **포착 47%**(중앙).
- AMGCL(150 기준 83%/43%)와 동등 → **예측 접근법이 hypre에도 일반화**.

## 2. 난이도 전이 — "어떤 조합이든 풀리는가?" (전이돼야 함, 그리고 됨)
행렬-수준 분류기를 한 라이브러리로 훈련→다른 라이브러리 테스트:
- train AMGCL → test hypre: acc **0.85** vs 다수결 0.59 (**lift +0.25**)
- train hypre → test AMGCL: acc **0.85** vs 다수결 0.52 (**lift +0.33**)
- **내재적 풀림 여부는 라이브러리 간 강하게 전이** → §6의 Jaccard 0.76(어려운 행렬
  겹침)을 예측기로 재확인.

## 3. 튜닝성 전이 — oracle 크기 (전이 안 돼야 함, 그리고 안 됨)
oracle 크기 회귀기를 한 라이브러리로 훈련→다른 쪽 예측-실제 순위상관:
- train AMGCL → test hypre: Spearman **0.23**
- train hypre → test AMGCL: Spearman **0.20**
- **튜닝 이득 크기는 라이브러리 간 전이 안 됨** → §6의 교차 oracle 상관 0.24를
  예측기로 재확인.

## 종합 (§6 완성)
예측기가 교차검증 스토리를 양방향으로 확증:
- 예측 접근법은 두 라이브러리 모두에 작동(87%/47% vs 83%/43%).
- **난이도(풀림)는 라이브러리 독립 → 강하게 전이**(+0.25~0.33).
- **튜닝성(oracle 크기)은 라이브러리 의존 → 전이 실패**(Spearman ~0.2).
행렬은 라이브러리-독립적 난이도 + 라이브러리-의존적 튜닝성을 가진다는 정교한 결론을,
예측기로 정량 입증. 논문 §6에 한 문단 추가.
